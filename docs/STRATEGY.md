## 1. 北极星

**VS Code 发行版不是 Cursor，也不是 Cline。**

我们以 **角色（灵魂）** 为基点：让 AI 角色 **活在开发者的工程与工作区里**——有记忆、有人设、有情绪表达；**IDE 如何渗透** 则交给 **可安装的插件** 与创作者自定义，而不是把官方扩展做成「自带全套效率工具」。

| 维度 | 基础聊天发行版（`desktop-chat`） | VS Code 发行版（`vscode`） |
|------|----------------------------------|----------------------------|
| **北极星** | 最流畅、最易用的纯聊天 | **角色在场** + **可扩展 IDE 渗透** + 创作空间 |
| **用户** | 所有人 | 有编码基础、愿意组装灵魂的开发者 |
| **差异化** | 零摩擦开聊 | 工作区里的角色 + **插件化** 留痕（日记/信等可选） |
| **明确不做** | IDE 渗透 | 照抄 Cursor 的代码劳动力定位；**也不做「最强效率套件」** |

学 Cursor 的是 **宿主可扩展、可审计**；不学的是 **「默认 Agent 改全仓库」** 与 **「官方包办一切渗透 UX」**。

## 2. 平台 vs 插件（2026-06 战略调整）

```text
┌─────────────────────────────────────────────────────────┐
│  oclive-vscode（核心 · 平台）                             │
│  聊天 · 内核 · 角色 · 身份 · 编辑器上下文 · 宿主 API       │
└───────────────────────────┬─────────────────────────────┘
                            │ 可选安装
┌───────────────────────────▼─────────────────────────────┐
│  渗透插件包（官方参考 + 第三方）                            │
│  日记 · 信 · idle · 终端一行 · .oclive/ · 模板           │
└─────────────────────────────────────────────────────────┘
```

| 原则 | 说明 |
|------|------|
| **合并交付** | 日记 + 写信 + 相关渗透 **一个插件包**，不在核心扩展里拆功能 |
| **插件优先** | 长期默认：**不装插件 = 纯聊天**；装插件 = 自选渗透方案 |
| **创作空间** | 官方提供 **契约 + 参考插件**；开发者可替换、删减、重写 |
| **效率边界** | OCLive **不必**在 IDE 效率上做到最好；**要给定制留位** |

详见 [`PENETRATION_PLUGIN_MODEL.md`](./PENETRATION_PLUGIN_MODEL.md)。

**0.3.2 说明**：内置 `src/penetration/*` 为 **过渡实现**，0.4 起迁移至独立插件并标记 deprecated。

## 3. 与 Cursor 的对照（不照抄）

| Cursor 强项 | OCLive VS Code 的回应 |
|-------------|------------------------|
| 强默认 coding Agent | **默认无内核 Agent 环**（`skip_agent`）；聊天主链仍是 `process_message` |
| 改代码 / 多文件 refactor | **非主战场**；渗透由 **插件** 定义，非核心扩展 |
| 规则 / 项目上下文 | **角色包** + `user_identities` + `reply_quality_anchor` |
| 插件与工具生态 | **六槽 + 目录插件 + MCP** + **VS Code 渗透插件** |
| 云会话 | **本地 8420** + 与桌面 **共享 `app.db`** |

**一句话**：Cursor 卖 **编码劳动力**；我们卖 **可组装的、住在 repo 里的角色** + **可插拔的 IDE 适配**。

## 4. 渗透 vs Agent（正交，不冲突）

| 能力示例 | 典型实现 | 需要 `agent ≠ none`？ |
|----------|----------|------------------------|
| 聊完后追加 `.oclive/{roleId}/diary.md` | **渗透插件** + 宿主写授权 API | **否** |
| 心声 / 信落盘 | **渗透插件** + 模板 | **否** |
| 当前文件选区进 prompt | 核心 `oclive.includeEditorContext` | **否** |
| 多步改文件 / MCP 工具链 | 六槽 **agent**（高级 profile） | **是** |

**战略结论**：核心做好 **VS-1 聊天**；**VS-2+ 渗透** 以 **插件** 交付；**VS-4 Agent** 仍为高级可选，不替代渗透插件。

## 5. 为何不限制开发者手脚

| 层 | 可定制手段 |
|----|------------|
| 发行版 | `distro.oclive.toml` / `OCLIVE_DISTRO_PROFILE` |
| 角色包 | `settings.json` · `plugin_backends` · `penetration_templates` |
| **渗透** | **安装/自写 VS Code 渗透插件**（非核心内置） |
| 会话 | 内核 HTTP 会话覆盖 |
| 高级 | 目录插件 · MCP · 可选 agent 槽 |

**流畅** = 装核心扩展、选角色就能聊；**可定制** = 渗透、工具、后端均可换，而不是锁死官方一种日记按钮。

## 6. 阶段路线（与 ROADMAP 对齐）

| 阶段 | 目标 | 落点 |
|------|------|------|
| **VS-1 聊天底座** | 与基础聊天同级流畅 | 核心扩展 · **Done** |
| **VS-2P 渗透插件化** | 日记+信+idle 等 **独立插件**；核心暴露宿主 API | `oclive-vscode-penetration` · 0.4 |
| **VS-3P 渗透生态** | 第三方插件样例 · 市场索引 · 创作者文档 | 0.4–0.5 |
| **VS-4 可选 Agent** | MCP · 多步工具（非默认） | 核心 + agent profile · **Done（胶水）** |

**VS-2/VS-3 内置渗透（0.3.x）**：已实现，**deprecated** → 迁移至 VS-2P。

## 7. 工程边界

1. **编排 SSOT** 仍在主仓 `process_message`；渗透 **不进内核编排**。
2. **`scene_id = vscode`** 固定。
3. **共享 `OCLIVE_APP_DATA`**：记忆跨宿主。
4. **写工作区** 经宿主 **授权 + 白名单**（核心 API 或插件调用同一审计链）。
5. **文档**：战略 **本文件**；插件模型 **PENETRATION_PLUGIN_MODEL.md**；API/设置 **VSCODE_DISTRIBUTION.md**。

## 8. 对外一句话

> **OCLive for VS Code**：把角色带进你的工程——聊得顺滑；**怎么渗透、怎么留痕，用插件自己定**。我们不是 Cursor，也不包办你的 IDE 效率工具。
